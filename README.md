**Tool-assisted speedrun (TAS) world records for every official [PolyTrack](https://www.kodub.com/apps/polytrack) track.** A TAS is a run whose inputs are planned frame by frame (1 frame = 1 ms) instead of played live, so it shows how fast each track can really be driven. Every run here is a normal PolyTrack recording, and CI replays it in the real game engine, downloaded from kodub.com, before it can go on the board. Nothing in the physics is changed.

**Anyone can compete:** beat a time, open a pull request, and the bot checks your run within minutes. → [How to submit](CONTRIBUTING.md)

## Submit a run

```bash
git clone https://github.com/nickita-khylkouski/polytrack-tas && cd polytrack-tas
npm install && npx playwright install chromium
npm run setup                                    # downloads the game engine + tracks from kodub.com (~20 s)
npm run add -- summer1 "<recording>" --author "your name" --github your-github
npm run verify -- runs/summer1/<file>.json       # the same check CI runs
```

Then open a pull request with the new file in `runs/`. Already uploaded your TAS to the in-game leaderboard? `npm run import -- summer1 --rank 1` pulls it straight from there. Details, the file format and the rules are in [CONTRIBUTING.md](CONTRIBUTING.md).

## Rules (short version)

1. **Official tracks, PolyTrack 0.6.3.** Summer 1–7, Winter 1–5, Desert 1–5.
2. **Any inputs, unchanged game.** Every frame can have any combination of up/right/down/left/reset. The run must finish in the official engine with every checkpoint taken, on exactly the frame it claims.
3. **Time = frames.** The finish frame is the time in ms, just like the game shows it. A tie goes to the earlier run.
4. **One entry per person per track.** Your fastest run counts. All accepted runs stay in `runs/` as history.

## How verification works

`tools/setup.cjs` downloads PolyTrack's own simulation worker and WASM physics from `app-polytrack.kodub.com/0.6.3/`, and grabs the worker's start-up message (track part and car collision meshes) from the real game in headless Chromium. `tools/engine.cjs` runs that worker in a Node VM. Its only hooks pass in the WASM bytes and expose the per-frame step, so the physics runs exactly as it does in the browser. `tools/verify.cjs` replays each run twice from a fresh car and checks the finish frame. As a self-test, all 170 runs in the in-game top 10s (10 per track) replay frame-exact this way (`npm run check-official`, run by CI on every push to main).

No game files are stored in this repository.

## FAQ

**Is this the official PolyTrack leaderboard?** No. It's an unofficial community board for TAS runs. Real-time human runs live on the [in-game leaderboard](https://www.kodub.com/apps/polytrack) and on [speedrun.com](https://www.speedrun.com/polytrack).

**Does a TAS change the game?** No. A TAS only chooses the inputs. The car, physics, timing, checkpoints and finish are the game's own, which is why the recordings replay in the unmodified engine.

**How are these runs made?** With any tool you like: savestate TAS tools, scripts, search or optimizer programs, or patience. Put what you used in the `tool` field.

**What about community tracks or other versions?** Not yet. Open an issue if you want them.
